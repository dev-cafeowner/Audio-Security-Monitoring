# NPU 기반 무인시설 환경음 분석 및 보안 모니터링 시스템

## 프로젝트 개요

Zynq SoC의 PL(Programmable Logic)과 PS(Processing System)를 활용한 환경음 분석 시스템입니다. 마이크로 수집한 소리 또는 준비된 데모 오디오를 FPGA NPU에서 분석하고, 결과를 PC UI에 보안 이벤트로 표시합니다.

NPU는 LeeNet11의 합성곱·전역 풀링·전결합 연산을 수행합니다. PS는 오디오 입출력, 데이터 전송, NPU 제어와 결과 후처리를 담당하고, PC UI는 마이크 감시와 데모 실행 제어, 현재 보안 상태 및 이벤트 기록 확인을 담당합니다. 노크·유리 파손·총성·화재경보를 대표 시연 대상으로 구성했습니다.

## 개발 배경

무인시설에서는 운영자가 현장에 상주하지 않아도 출입 활동, 파손음, 경보음 등의 상황을 확인할 필요가 있습니다. 음향은 영상에서 직접 보이지 않는 상황을 파악하는 데 활용할 수 있는 정보입니다.

환경음 분류 모델의 반복적인 곱셈·누산 연산을 FPGA에서 병렬 처리하고, 제어와 이벤트 판단은 PS에서 처리하도록 역할을 나누었습니다. 오디오 입력부터 신경망 추론, 결과 전달과 모니터링 화면까지 연결하여 임베디드 환경에서 동작하는 보안 모니터링 시스템을 구현하는 것이 이 프로젝트의 배경입니다.

## 개발 목표

| 목표 | 설계 방향 |
|---|---|
| 환경음 기반 상태 파악 | 527개 AudioSet 클래스의 모델 출력을 활동·침입 및 파손·중대 위험·시설 비상 등의 보안 상태로 정리 |
| NPU 연산 가속 | 반복적인 곱셈·누산 연산을 병렬화하고, 합성곱과 전결합 계층이 계산 자원을 공유하도록 구성 |
| PL·PS 역할 분담 | 신경망 연산은 PL, 오디오 및 DMA 제어·계층 실행 관리·결과 후처리는 PS에서 수행 |
| 마이크·데모 입력 통합 | 실제 마이크 입력과 사전 준비된 PCM 데이터를 동일한 NPU 추론 경로로 처리 |
| PC 모니터링 | UART를 통해 감시 명령과 결과를 주고받고 보안 상태, 대표 감지음, 이벤트 기록을 표시 |
| 검증 가능한 모델 구성 | Python 기준 모델, 원본 가중치, NPU용 가중치 및 데모 입력을 함께 관리 |

## 프로젝트 구성

### 시스템 구조

공통 추론 경로는 `마이크·데모 입력 → DDR → AXI DMA → NPU → DDR → PS 후처리 → UART → PC UI`로 구성됩니다.

| 구성 요소 | 주요 역할 |
|---|---|
| 마이크 입력 | SSM2603 ADC와 I²S 수신부로 오디오를 수집하고, Audio Formatter를 통해 DDR에 저장 |
| 데모 입력 | DDR에 적재된 노크·유리 파손·총성·화재경보 PCM 데이터를 NPU 입력으로 사용 |
| 오디오 재생 | 데모 데이터를 I²S 송신부와 코덱 DAC로 전달하여 보드에서 재생 |
| 데이터 저장·전송 | AXI DMA로 NPU 입출력을 전송하고, 계층별 중간 결과를 DDR 버퍼에 저장 |
| NPU Core | 곱셈·누산, 활성화, 풀링, 재양자화 및 출력 범위 제한을 수행하는 계산부 |
| NPU Top | NPU Core에 입력과 가중치를 공급하고 내부 버퍼, 계층 제어 및 AXI 인터페이스를 연결 |
| PS Application | 코덱 설정, 입력 모드 선택, DMA 제어, 12개 계층 실행 및 보안 이벤트 후처리 |
| PC UI | 감시 시작·정지와 데모 실행 명령 전송, 결과 수신, 이벤트 표시 및 CSV 기록 |

PS는 NPU에 12개 계층을 순차적으로 실행시키며, 중간 결과는 두 DDR 버퍼를 번갈아 사용해 전달합니다. NPU의 최종 출력은 527개의 INT16 분류 점수입니다. PS는 이를 클래스별 점수로 변환하고, 보안 그룹의 임계값과 우선순위에 따라 표시할 상태와 대표 감지음을 선택합니다.

### 모델 및 NPU 연산 구조

LeeNet11은 원시 오디오 파형을 입력받는 1차원 합성곱 모델입니다. Python 기준 모델은 FP32로 동작하며, 보드의 NPU는 INT16 입력·가중치와 48비트 누산기를 사용합니다.

| 연산 구간 | 주요 처리 |
|---|---|
| Conv1 | 커널 크기 3, 이동 간격 3으로 초기 특징 추출 |
| Conv2~Conv9 | 합성곱·ReLU·MaxPool을 반복하며 채널 특징을 확장하고 시간축 길이를 축소 |
| Global Pool | 시간축의 최대값과 평균값을 합산하여 256차원 벡터 생성 |
| FC1 | 256 → 512차원 변환 및 ReLU |
| FC2 | 512 → 527개 클래스의 최종 분류 점수 생성 |

계산부는 출력 채널 16개, 커널 위치 3개, 입력 채널 4개를 동시에 처리하도록 구성했습니다. 이에 따른 최대 병렬 연산량은 `16 × 3 × 4 = 192 MAC/cycle`입니다. 이 값은 계산 자원이 모두 활용될 때의 최대치이며, 전체 실행 시간에는 데이터 공급과 제어에 필요한 시간이 함께 반영됩니다.

Python 모델은 원본 학습 가중치를 이용한 기준 추론에 사용합니다. 실제 보드의 추론은 FPGA NPU가 담당하며, NPU용 가중치는 고정소수점 형식과 하드웨어가 읽는 순서에 맞춰 별도로 구성되어 있습니다.

### 입력 모드와 모니터링

- 마이크 모드: 연속으로 오디오를 수집하면서 10초 입력 창을 5초씩 이동해 분석합니다. PC UI에서 감시를 시작하거나 정지할 수 있으며, 보드 오디오 출력은 비활성화됩니다.
- 데모 모드: 노크·유리 파손·총성·화재경보 중 하나를 선택해 추론합니다. 동일한 입력을 보드에서도 재생하여 음향과 결과를 함께 확인할 수 있습니다.

PC UI는 현재 보안 상태, 대표 감지 음향, 진행 중인 이벤트와 이벤트 발생 기록을 표시합니다. UART는 명령과 분석 결과를 전달하며, 오디오 샘플 자체를 PC로 전송하지는 않습니다.

이벤트의 지속 시간은 10초 분류 입력 창에 기반한 검출 범위입니다. 입력 창 안에서 특정 소리가 실제로 발생한 길이를 직접 측정한 값은 아닙니다.

## 프로젝트 결과

### NPU 성능 및 하드웨어 구현 결과

전체 SoC의 배치·배선 보고서와 검증된 데모 입력의 실보드 실행 로그를 기준으로 정리한 결과입니다.

| 항목 | 결과 | 확인 기준 |
|---|---:|---|
| 실제 PL 클록 | 76.923 MHz | 구현된 클록 설정 |
| DSP48E1 사용량 | 192개 | 전체 SoC 배치·배선 보고서 |
| LUT / FF 사용량 | 43,565 / 58,801 | 전체 SoC 배치·배선 보고서 |
| Conv2 연산 사이클 | 6,826,911 cycles | 실보드 실행 로그 |
| Conv2 계산 단계 수 | 6,826,688 steps | 입력 채널 4개를 함께 처리하는 연산 구성 |
| 12계층 연산 시간 합계 | 213.092 ms | 실보드 계층별 실행 시간의 합 |
| 셋업 시간 여유 WNS | +0.260 ns | 전체 SoC 배치·배선 타이밍 분석 |
| 유지 시간 여유 WHS | +0.018 ns | 전체 SoC 배치·배선 타이밍 분석 |

213.092 ms는 10초 길이의 오디오 입력에 대한 12개 계층의 연산 시간 합계입니다. 마이크가 최초 10초 입력을 수집하는 시간, 계층 실행 바깥의 처리와 PC 화면 표시 시간을 모두 포함한 시스템 전체 응답 시간은 아닙니다.

### 구현 성과와 검증 범위

| 검증 항목 | 확인 결과 |
|---|---|
| NPU 고정소수점 연산 | 기준 출력(Golden)과 12/12 계층 일치, 최종 527/527개 출력값 일치 |
| 오디오·NPU 통합 | 데모 입력의 추론 완료, UART 결과 출력 및 보드 오디오 재생 확인 |
| Python 기준 모델 | 748,367개 파라미터의 원본 체크포인트 복원 및 네 데모의 Top-5 결과 재현 |
| PC UI 제어·표시 | 오프라인 시험에서 MIC 시작·정지, 네 데모 명령, 이벤트 기록과 완료 상태 표시 확인 |
| 배포 데이터 일치 | 원본 체크포인트, NPU 가중치 및 WAV·PCM이 검증에 사용한 파일과 일치 |

Golden 비교는 확인한 입력에서 NPU가 고정소수점 기준 모델과 같은 값을 계산하는지 검사한 결과입니다. 실제 시설에서 모든 소리를 정확히 분류한다는 의미는 아닙니다. 마이크 감지 결과는 스피커·마이크의 특성, 거리, 음량과 주변 소음에 영향을 받으며, 데모 네 가지의 결과는 일반적인 현장 인식률과 구분합니다.

### 남은 과제

- 다양한 거리·음량·배경 소음과 혼합음 조건에서 오탐·미탐 평가
- 분류 입력 창보다 세밀한 시간 구간을 이용한 이벤트 발생 시점·지속 시간 추정
- 부하와 전원 조건을 확대한 소비전력·장시간 안정성 검증
